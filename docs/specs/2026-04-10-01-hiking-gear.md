# Hiking Gear — Project Spec

Personal lighterpack replacement for a single user (me), seeded from an export of my existing lighterpack account.

## Goals

- Own my data. Full export from lighterpack.com, stored locally.
- Parity with lighterpack's trip view as the baseline UX.
- Room to grow with new features lighterpack doesn't have — starting with a **Template** feature based on a curated 3-season backpacking list.
- Deployable to my home server later; not a public service.

## Non-goals

- Multi-user, auth, registration, password reset.
- Public shared links / moderation / image uploads.
- Mobile app. Web works on mobile; that's enough.
- Feature-complete parity with every lighterpack niche (pie chart polish, CSV export variants, legacy unit hacks, etc.) until I actually want them.

## Architecture

- **Backend**: Node + Hono, SQLite via better-sqlite3. Single file at `data/hiking-gear.db`. Relational schema, not a JSON blob.
- **Frontend**: Vite + React + TypeScript. SPA served by Vite in dev; static build later.
- **Storage**: everything in one sqlite file. Items are a shared library (reused across lists). Each list owns its own categories. Category-items is a junction with qty/worn/consumable/star.
- **Templates**: separate set of tables. A template is a named, ordered catalog of categories and items with a default priority level. Templates are imported from external sources (currently the 3-season CSV). Templates are never mutated by trip edits.
- **Deployment**: later, via the beebaby deploy skill.

## Data model (conceptual)

- `settings` — kv for units, currency symbol, default list id, optional-field toggles.
- `items` — shared item library. Fields: name, description, weight (milligrams, float), author unit, price, image, imageUrl, url.
- `lists` — trips. Fields: name, description, external id, position.
- `categories` — belong to exactly one list. Fields: name, color, position.
- `category_items` — junction with qty, worn, consumable, star, position.
- `templates` — slug, name, source url.
- `template_categories` — belong to one template. Name, position.
- `template_items` — belong to one template category. Name, priority (Critical/Contingent/Suggested/Optional/Unnecessary), description, example, more-info, position. Not linked to the shared item library — a template item is a recommendation, not a concrete gear piece.

## Units and math

- All weights stored as milligrams (matches lighterpack so migration is lossless).
- Display unit is per-item (`authorUnit`) or per-list (`totalUnit`).
- Totals formulas match lighterpack:
  - Weight = Σ (item.weight × qty)
  - Worn weight = Σ (item.weight) for items with worn=true AND qty>0 (weight counted once, not multiplied)
  - Consumable weight = Σ (item.weight × qty) for items with consumable=true
  - Base = Total − Worn − Consumable
  - Pack = Total − Worn

## Features

### Shipped

1. **Lighterpack export** (`scripts/export-lighterpack.mjs`)
   - POSTs `/signin` to lighterpack.com, dumps the full library JSON into `data/lighterpack/<timestamp>/` as split files (raw, library, items, categories, lists, settings, summary, session cookie).
   - Re-runnable. One export dir per run.

2. **Import from lighterpack export** (`server/import.ts`)
   - Reads the most recent export dir.
   - Wipes lists/categories/category_items, upserts items, re-inserts everything with original IDs preserved.
   - Orphan categories (not reachable from any list) are dropped.

3. **3-season template import** (`server/import-template.ts`)
   - Parses `reference/template/3-season.csv` (Andrew Skurka's 3-season backpacking list).
   - Category header rows are detected by column A matching column F. TOTAL / blank rows are skipped. Repeated category blocks (per-trip variants) are deduplicated by category name.
   - Only template-level fields are kept: item name, default priority, description, example, more-info. Per-trip "selection" columns are ignored.

4. **Read-only trip view**
   - Lands on the highest-id list by default.
   - Header: list switcher (newest first), list name, description.
   - Totals row with Base/Worn/Consumable/Pack/Total/Items/Price.
   - Category sections with per-category subtotal and items table (qty, name, description, worn, consumable, weight + author unit, price).

### Next up

5. **Template browse + create-trip-from-template**
   - `/templates` screen listing templates with category/item counts.
   - Template detail view showing categories with items grouped by priority (Critical first, then Contingent, Suggested, Optional; Unnecessary hidden by default).
   - "New trip from template" action:
     - Creates a new list.
     - Clones selected template categories into real categories on the new list.
     - For each template item the user chose to include, create-or-reuse an item in the shared library (match by name) and link via category_items with qty=1, worn/consumable flags default false.
     - Priority-based pre-selection: Critical = checked, Contingent = checked, Suggested = unchecked, Optional = unchecked. User can toggle.
     - "Include weight placeholders?" option: if yes, weight = 0 and flagged incomplete so the trip view can highlight rows still needing a real weight.

6. **Trip editing**
   - Inline edit of list name, description.
   - Add/edit/delete categories on a list. Reorder by drag.
   - Add/edit/delete items within a category. Edit qty, worn, consumable flags inline. Reorder by drag.
   - Item picker: search the shared library when adding to a category so existing items can be reused across trips.
   - New item form: name, description, weight + unit, price, url (no image upload in v1 — imageUrl pasted in).
   - Save-on-blur; no explicit save button.
   - Optimistic UI, with error recovery if the API rejects.

7. **Trip lifecycle**
   - Clone a trip (copy list + categories + category_items, shared items stay shared).
   - Delete a trip.
   - Archive / unarchive (hide from default list switcher but keep in data).

8. **Item library management**
   - `/items` screen — browse and edit the shared item library.
   - Show which trips use each item.
   - Warn before deleting an item that's still referenced.

9. **Per-section meters (future)** — distance/time estimates per category or per item for on-trail planning. Placeholder; flesh out when the rest is stable.

10. **Deployment**
    - Static frontend build served by Hono itself, single Node process.
    - Deploy via the beebaby skill as a user systemd service.
    - Sqlite file lives in a persistent volume on the server.

11. **Gear quantity controls & "leave it off" state** — see `2026-04-10-02-gear-quantity-controls.md`. Adds a `singleton` flag to items (most gear is qty=1, so the UI should optimize for that) and treats `qty=0` as a persistent "trying on" state with a dimmed row, Keep it / Remove controls. Overriding singleton qty is via a pencil affordance.

## Open questions

- **Template-to-item linkage**: should a template item ever reference a real item in the shared library, or are they always just suggestions? Current answer: always just suggestions. Reuse happens by name-match at trip-creation time.
- **Priority in trips**: do we keep the priority level on a category_item once a template is instantiated? Useful for "must-have" filtering later. Leaning yes — add a nullable `priority` column to `category_items`.
- **Weight unit per item vs per list**: lighterpack supports both `authorUnit` (per item) and `totalUnit` (per list display). Keep both. No change.
- **Sync back to lighterpack?** No. One-way export at the start, then this is the source of truth.
