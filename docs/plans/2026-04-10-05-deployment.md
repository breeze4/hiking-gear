# Batch D — Deployment

Production build, Hono serving the static SPA, and a deploy scaffold for the beebaby home server. **Do not actually deploy** — just scaffold.

## Scope

Build & serve:
- [ ] `npm run build` produces `dist/`
- [ ] Add `start` script: `"start": "NODE_ENV=production tsx server/index.ts"`
- [ ] In `server/index.ts`, when `NODE_ENV === 'production'`:
  - [ ] Serve `dist/` as static files
  - [ ] SPA fallback: non-API GETs that miss a static file return `dist/index.html`
  - [ ] Skip the SPA fallback for any path starting with `/api`
- [ ] Dev unchanged

Deploy scaffold:
- [ ] Run `deploy-to-beebaby` skill, configure for `hiking-gear`, port from env (default 3000), persistent volume for `data/hiking-gear.db`, rsync deploy
- [ ] Inspect resulting deploy script and systemd unit

Verification:
- [ ] `npm run build` clean
- [ ] `NODE_ENV=production PORT=3001 tsx server/index.ts` boots and serves the app
- [ ] agent-browser: open `:3001/`, navigate `/templates`, `/items`, refresh on a deep route → SPA fallback works
- [ ] `/api/lists` returns JSON
- [ ] Screenshots: deploy-prod-home, deploy-prod-deep-route
- [ ] Inspect systemd unit
- [ ] Stop prod server. Close browser. Do NOT run deploy.

## Results

Shipped:

- `package.json`: added `"start": "NODE_ENV=production tsx server/index.ts"`. The build script (`vite build`) was already in place.
- `server/index.ts`:
  - When `NODE_ENV === 'production'`, mount `serveStatic({ root: './dist' })` for all paths
  - Final catch-all returns `dist/index.html` for any non-`/api` path that wasn't matched. `/api/*` falls through to a 404 instead of getting the SPA.
  - Behavior in dev is unchanged because the production block is gated on the env var.
- `deploy/deploy.sh`, `deploy/setup.sh`, `deploy/hiking-gear.service` written via the `deploy-to-beebaby` skill (and chmod +x). Adapted from the `beebaby-admin` reference:
  - rsync excludes: `node_modules`, `.git`, `dist`, `data`, `screenshots`, `.env`. **`data` is excluded** so the persistent SQLite file at `~/dev/hiking-gear/data/hiking-gear.db` is never overwritten or deleted by `--delete`.
  - systemd unit: `WorkingDirectory=%h/dev/hiking-gear`, `ExecStart=/usr/bin/npm start`, `Restart=always`, env vars `NODE_ENV=production`, `PORT=3000`, `DB_PATH=%h/dev/hiking-gear/data/hiking-gear.db`, installed under `default.target` (correct for user units).
  - `setup.sh` creates the data dir and enables linger so the user service survives reboots.

Verification:

- `npm run build` clean. `dist/` contains `index.html` and `assets/`. Bundle: 261 kB JS / 14 kB CSS pre-gzip.
- `NODE_ENV=production PORT=3001 npx tsx server/index.ts` boots and prints `hiking-gear api listening on http://localhost:3001`.
- agent-browser at `http://localhost:3001/`: home renders, `/items` deep route renders, reload on `/items` still serves the SPA via the fallback (URL stays `/items`, link bar still shows Items + Templates), `/api/lists` returns JSON via `curl`.
- Screenshots: `screenshots/deploy-prod-home.png`, `screenshots/deploy-prod-deep-route.png`.
- Stopped the prod server. Browser closed.

Systemd unit sanity-check (against the rules in CLAUDE-style notes):

- `Description=Hiking Gear` ✓
- `Type=simple` ✓
- `WorkingDirectory=%h/dev/hiking-gear` ✓ — relative to `$HOME` so it works for whatever user runs it
- `ExecStart=/usr/bin/npm start` ✓ — invokes the new `start` script which `tsx`-runs `server/index.ts`. Avoids hard-coding the path to `node_modules/.bin/tsx`.
- `Restart=always` + `RestartSec=5` ✓
- `Environment=DB_PATH=…` ✓ — points the server at the persistent file outside `dist/` and outside the rsync sweep
- `User=` is intentionally omitted; this is a **user** systemd unit installed under `~/.config/systemd/user/`, so it runs as whoever loaded it.
- `WantedBy=default.target` ✓ (correct for user units, not multi-user.target).

Deploy NOT run.

To deploy in the future:

1. `ssh beebaby 'bash -s' < deploy/setup.sh` (one time)
2. Optionally copy the dev `data/hiking-gear.db` to `beebaby:~/dev/hiking-gear/data/hiking-gear.db` so the production instance starts with the existing library.
3. `./deploy/deploy.sh`

Deviations:

- `ExecStart=/usr/bin/npm start` instead of a hard-coded `node …/tsx server/index.ts`. Reason: the project already has a `start` script and using it keeps the deploy unit a single source of truth. Cost: it spawns an extra `npm` process which becomes the systemd PID parent — fine for `Type=simple`.
- The skill template suggests `--exclude='node_modules'` and similar; I added `data`, `screenshots`, and `.env` for this project.

Open questions:

- The spec says the SQLite file lives in a "persistent volume". For beebaby this just means a path that survives deploys; `~/dev/hiking-gear/data/hiking-gear.db` (excluded from rsync --delete) does the job. If you ever want to back it up off the box, that's separate.
- No reverse proxy (Caddy / nginx) configured here. Currently the systemd unit binds `:3000` directly. If beebaby fronts services with a proxy, you may need a virtual host pointing at `localhost:3000`.
